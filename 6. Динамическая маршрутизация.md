
>Создаем процесс OSPF, объявляем сети, исключаем интерфейс из процесса OSPF, оставляя в этом процессе лишь туннель, после чего включаем аутентификацию для всех интерфейсов определенной области, в том числе сегментов сети area 0. 1. 
>	1. `router ospf 1` - включает процесс OSPF с идентификатором 1. Идентификатор процесса локально значимый. 1. 
>		2. `passive-interface` -  default Делает все интерфейсы маршрутизатора пассивными по умолчанию. Это означает, что OSPF не будет отправлять Hello пакеты или формировать соседство на **всех** интерфейсах.
>			3.`area 0 authentication` - Включает аутентификацию OSPF для Area 0. Это означает, что все OSPF пакеты, отправляемые и получаемые в Area 0, должны быть аутентифицированы с использованием настроенного метода аутентификации. 

==HQ-RTR==


```
en
	conf t
	router ospf 1
		network 172.16.0.0/30 area 0
		network 192.168.1.0/27 area 0
		network 192.168.2.0/28 area 0
		passive-interface default
		no passive-interface tunnel.0
		area 0 authentication
		exit
	write memory 
```


> Аналогичные действия выполняем и на `BR-RTR`

==BR-RTR==

```
en
	conf t 
	router ospf 1
		network 172.16.0.0/30 area 0
		network 192.168.3.0/28 area 0
		passive-interface default
		no passive-interface tunnel.0
		area 0 authentication
		exit
	write memory
```

*Объяснение:*
	1. **router ospf 1** — запускает процесс OSPF с ID 1
	2. **network 172.16.4.0/28 area 0** — включает интерфейсы из подсети 172.16.4.0/28 в зону 0 (backbone)
	3. **network 192.168.1.0/26 area 0** — добавляет сеть 192.168.1.0/26 в OSPF
	4. **network 192.168.2.0/28 area 0** — добавляет сеть 192.168.2.0/28 в OSPF
	5. **passive-interface default** — отключает рассылку OSPF-пакетов на всех интерфейсах по умолчанию
	6. **no passive-interface tunnel.0** — исключает туннель из passive-режима (разрешает OSPF на нем)
	7. **area 0 authentication** — включает аутентификацию для зоны 0 (требуется ключ, заданный ранее в tunnel.0)
	8. **exit** — завершает конфигурацию OSPF
